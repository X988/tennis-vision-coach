# Архитектура

Все подсистемы работают от **одного simulationTime** (`SimulationClock`), одной системы
координат и одного описания сценария. Сценарий → план рассчитывается целиком заранее,
поэтому мяч, игрок, ракетка, подсказки и таймлайн не могут разойтись по фазам. Любое
изменение мяча или профиля заново прогоняет всю цепочку (критический инвариант ТЗ, раздел 5).

```
ScenarioSpec (JSON, zod) ──► plan.ts: buildPlan(scenario, profile, {variant, stance})
   │  1. Ball Engine          ball.ts          полёт: сопротивление, Магнус, отскок с трением
   │  2. Reachability Engine  reachability.ts  реакция, разгон, макс. скорость, окно контакта
   │  3. Decision Engine      decision.ts      стойка / первый шаг / подготовка / точка контакта
   │  4. Animation input      plan.ts          шаги, путь таза, повороты, ключи ракетки
   │  5. Ответный удар        physics.ts       solveLaunch к цели по задаче (нейтр./атака/защита)
   ▼
Plan ──► motion.ts: poseAt(motion, t)   Animation Engine: суставы, IK ног и рук
     ──► feedback.ts                    Feedback Engine: варианты ответа, оценка, прогресс
     ──► app/scene/*                    отрисовка (React Three Fiber), только читает план
```

## Модули (`src/engines`, без зависимостей от React)

| Модуль | Ответственность |
| --- | --- |
| `vector.ts` | векторная математика |
| `court.ts` | координаты корта ↔ 3D-мира |
| `physics.ts` | константы ITF, покрытия, RK4, отскок, решатель угла вылета |
| `ball.ts` | Ball Engine: скорость до отскока + точка отскока + высота траектории |
| `profile.ts` | профиль; реакция, разгон, скорость, время постановки по уровню и росту |
| `technique.ts` | библиотека техники: ключевые позы ударов, раскладка стоп для 4 стоек |
| `reachability.ts` | кандидаты контакта, запас времени, защитная альтернатива, «не успевает» |
| `decision.ts` | правила тренера (данные, версия `COACH_RULES_VERSION`), варианты с причинами и уверенностью |
| `plan.ts` | сборка плана, ошибки для режима сравнения, события и фазы |
| `motion.ts` | Animation Engine: стопы (стоят или переносятся — без скольжения), таз, IK, ракетка |
| `feedback.ts` | вопросы, оценка ответа, записи прогресса |
| `clock.ts` | общий simulationTime: пауза, кадр, фазы, скорость |
| `scenario.ts` | схема сценария, валидация, зеркалирование для левшей |

## Фазы (конечный автомат FR-03)

готовность → удар соперника → split-step → чтение мяча / разворот → перемещение →
постановка ног → ускорение ракетки → контакт → сопровождение → восстановление → итог.
Разворот идёт параллельно с перемещением (ранняя подготовка), ускорение ракетки
начинается только за `forwardSwing` секунд до контакта.

## Гарантии (проверяются тестами)

- ракетка в точке мяча при контакте (< 1 см) для всех сценариев;
- опорная стопа не смещается, нога дотягивается до неё (таз опускается автоматически);
- головка ракетки не проходит через корпус;
- левша — зеркальная логика (удар другой стороной, ракетка в левой руке);
- недостижимый мяч: «не успевает», игрок бежит, но не телепортируется;
- каждая ошибка в режиме сравнения меняет результат.

## Клиент

`src/app`: экраны, сцена R3F, i18n (ru полностью; uk и en — структура с откатом на ru),
состояние (`localStorage` — профиль, настройки, рабочее состояние; IndexedDB — прогресс),
PWA (vite-plugin-pwa, офлайн-кэш). Качество графики: авто (снижение теней и разрешения
при падении FPS, подсказки не отключаются) / высокое / экономное.

## Обучение пользователя

`src/app/tour`: `steps.ts` — упорядоченный список шагов (экран, подсвечиваемый элемент
`data-tour="…"`, условие завершения), `Tour.tsx` — приветствие первого запуска и оверлей
с подсветкой. Пока тур активен, урок работает в учебном режиме (`useTour().active`) и не
пишет в прогресс. Тексты шагов — в `i18n` (`tour.*`), экран «Справка» использует их же,
поэтому описание кнопки существует в одном месте. Тест `steps.test.ts` проверяет, что у
каждого шага есть текст и что тур проходит все экраны и режимы.

## Модель игрока

`app/scene/Athlete.tsx` строит тело один раз и каждый кадр расставляет части по суставам
из `motion.ts`: конечности — суживающиеся сегменты с шарами-суставами, торс — три объёма
(таз, талия, грудь), которые следуют за тазом и плечами раздельно, поэтому видно
скручивание корпуса. Соперник — та же модель с планом `buildOpponentMotion` в системе
координат, повёрнутой на 180°.
